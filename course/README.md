# Open-source курс «Анализ данных в научной литературе»

Курс устроен как совместная разработка: участники изучают ML, графы, работу с научными текстами и оценку моделей, одновременно улучшая один общий открытый инструмент.

## Что отличает этот формат

- **Не одинаковые домашки, а разные роли.** Можно внести код, научную экспертизу, данные, тест, инструкцию или организационное улучшение.
- **Не одноразовая оценка, а живой артефакт.** Работа проходит ревью и остаётся полезной после курса.
- **ИИ — рабочий инструмент, а не замена ответственности.** Сгенерированные ответы, код и ссылки проверяются участником.
- **Сложность делится на безопасные шаги.** У каждой задачи есть контекст, пример, шаблон и критерий готовности.
- **Методика тоже открыта.** Другой преподаватель или сообщество могут повторить курс и предложить улучшения.

## Результат курса

Участник должен не только «знать тему», но и оставить проверяемый вклад в общую систему:

- merged pull request;
- принятый экспертный артефакт;
- воспроизводимый notebook или эксперимент;
- тест, который предотвращает повторение ошибки;
- учебный материал, по которому сможет пройти следующий человек;
- публичный набор данных, benchmark или отчёт с ясными ограничениями.

## Перед первой неделей

1. Прочитайте [путь контрибьютора](CONTRIBUTOR_GUIDE.md).
2. Установите проект через `scripts/bootstrap.sh` или `bootstrap.ps1`.
3. Запустите `top-papers-graph demo-run --llm-provider mock`.
4. Выберите роль на первый спринт; её можно менять по ходу курса.
5. Возьмите небольшую задачу и договоритесь о критериях готовности.

## Программа

| Неделя | Тема | Типичный вклад |
|---:|---|---|
| 1 | Вход в проект и воспроизводимое демо | исправление онбординга, issue, smoke-test |
| 2 | PDF -> текст -> чанки | тестовый документ, оценка качества разбора, parser fix |
| 3 | Термины и доменные словари | словарь, нормализация, сравнение извлекателей |
| 4 | Связи и триплеты | проверенные связи, фильтр шума, extraction test |
| 5 | Темпоральность | временная коррекция, метрика тренда, regression case |
| 6 | Графовые алгоритмы | анализ сообществ, пути, объяснимый пример |
| 7 | Link prediction | кандидаты гипотез и критерии их проверки |
| 8 | Векторные представления | baseline, абляция, сравнение ранжирования |
| 9 | Code agents | новый tool, sandbox rule, воспроизводимое сравнение |
| 10 | Human-in-the-loop | graph/hypothesis review, gold-набор, data pipeline |
| 11 | GNN/TGNN и оценка | holdout, метрики, честная проверка модели |
| 12 | Интеграция и публичный результат | итоговый PR, demo, dataset или release note |

Подробности находятся в [`course/weeks/`](weeks/).

## Роли

Роли помогают разделить сложность, а не ранжировать участников.

- **Исследователь:** задаёт научный вопрос и собирает evidence.
- **Эксперт:** проверяет смысл и ограничения утверждений.
- **Разработчик:** реализует и тестирует систему.
- **Координатор:** делает процесс понятным и доступным другим.

На одной неделе участник может объединять несколько ролей. Подробная карта ответственности: [docs/roles.md](../docs/roles.md).

## Как оценивается вклад

Основные критерии:

1. **Полезность:** изменение решает понятную задачу проекта.
2. **Проверяемость:** есть источник, тест, пример или процедура проверки.
3. **Воспроизводимость:** другой участник может повторить результат.
4. **Качество коммуникации:** контекст и ограничения описаны ясно.
5. **Совместность:** вклад облегчает следующий шаг другим людям.

Объём кода сам по себе не является критерием.
