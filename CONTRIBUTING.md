# Как внести вклад

`top-papers-graph` объединяет учебный курс и реальный open-source проект. Вкладом считается не только код: научная экспертиза, проверка данных, документация, тестирование и помощь с онбордингом имеют одинаковую ценность.

## 1. Выберите тип вклада

- **Код и инфраструктура:** исправление ошибки, тест, новый коннектор, улучшение CLI или пайплайна.
- **Научная экспертиза:** reasoning trajectory, проверка связи в графе, рецензия гипотезы, временная коррекция.
- **Учебные материалы:** пример, пояснение, перевод, задание, рубрика или улучшение инструкции.
- **Сообщество:** triage issues, воспроизведение ошибки, ревью pull request, помощь новичку.

Для первого шага используйте [course/CONTRIBUTOR_GUIDE.md](course/CONTRIBUTOR_GUIDE.md).

## 2. Перед началом

1. Проверьте существующие issues и pull requests.
2. Для заметного изменения создайте issue с целью, ожидаемым результатом и критериями готовности.
3. Не добавляйте закрытые PDF, API-ключи, персональные данные и файлы без понятной лицензии.

## 3. Рабочий процесс

```bash
git checkout -b feat/short-description
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest -q
```

Сделайте небольшое связное изменение, добавьте или обновите тесты и документацию. Перед PR выполните как минимум проверки затронутого модуля.

Рекомендуемые имена веток:

- `course/...` — учебная программа и задания;
- `docs/...` — документация;
- `data/...` — экспертные артефакты;
- `feat/...`, `fix/...`, `test/...` — код.

## 4. Куда класть результат

- учебные модули — `course/`;
- инструкции к заданиям — `docs/course/tasks/`;
- канонические блокноты — `notebooks/`;
- экспертные данные — `data/experts/<artifact_type>/`;
- код — `src/scireason/`;
- тесты — `tests/`;
- исследовательские эксперименты — `experiments/`.

Не коммитьте `runs/`, runtime-логи, временные PDF, notebook outputs, `*.egg-info`, кэши и автоматически сгенерированные отчёты.

## 5. Pull request

В описании укажите:

- проблему и смысл изменения;
- роль, для которой изменение полезно;
- как воспроизвести или проверить результат;
- какие файлы данных и внешние источники использованы;
- где применялся ИИ и что было проверено вручную.

PR считается готовым, когда он понятен другому участнику, не требует скрытого контекста и проходит соответствующие проверки.

## 6. Использование ИИ

ИИ можно использовать для поиска вариантов, написания черновиков и кода. Нельзя принимать его вывод без проверки. Автор PR отвечает за:

- корректность кода и вычислений;
- соответствие источникам;
- отсутствие вымышленных цитат;
- безопасность и лицензирование данных;
- ясное описание ограничений.

## 7. Ревью

Ревью оценивает не «уровень» участника, а качество конкретного вклада: полезность, проверяемость, воспроизводимость, ясность и бережное отношение к другим контрибьюторам.


## Лицензирование вкладов

Отправляя issue с вложениями, commit или pull request, вы подтверждаете, что имеете право передать этот вклад проекту и лицензируете его по `GPL-3.0-or-later`. Не добавляйте сторонний код, данные, изображения или тексты без совместимой лицензии и необходимой атрибуции. Подробности: [LICENSE_SCOPE.md](LICENSE_SCOPE.md).
